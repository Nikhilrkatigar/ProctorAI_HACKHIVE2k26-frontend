# PWA Features - ProctorAI

ProctorAI now includes Progressive Web App (PWA) capabilities for improved offline support, app-like experience, and installability.

## Features Enabled

### 1. **Offline Support**
- Caches API responses and images for offline access
- Network-first strategy for API calls (tries network first, falls back to cache)
- Cache-first strategy for images (faster loading)
- Graceful degradation when offline

### 2. **App Installation**
- **Web**: Installable on desktop and mobile via "Add to Home Screen"
- **Android**: Creates app shortcut with standalone display mode
- **iOS**: Add to Home Screen creates app-like experience
- **Windows**: Can be installed via App Store integration

### 3. **Service Worker**
- Auto-updates when new version is available
- User prompt to update to latest version
- Offline detection with status indicator
- Background sync for exam data (when connectivity returns)

### 4. **Manifest Features**
- App metadata and branding
- App icons for all platforms (192x192, 512x512)
- App shortcuts for quick access:
  - "Start Exam" - Direct link to exam page
  - "Proctor Dashboard" - Direct link to dashboard
- Screenshots for app store listing
- Multiple theme colors and categories

## Usage

### Installation on Different Platforms

**Desktop (Chrome/Edge)**
1. Click the install icon in the address bar (if available)
2. Or: Menu → "Install ProctorAI"

**Mobile (Android)**
1. Open ProctorAI in Chrome
2. Tap menu → "Install app"
3. App appears on home screen

**iOS**
1. Open ProctorAI in Safari
2. Tap Share → "Add to Home Screen"
3. App appears on home screen

### Offline Mode
- When offline, an indicator appears at the bottom-left
- Cached content (login page, previous exam questions) remains available
- API calls are queued and sync when connection returns

### Update Notification
- When a new version is available, a toast notification appears
- Click "Update" to reload with latest version
- "Later" dismisses the notification

## Cache Strategy

### API Cache (Network-First)
- Endpoint: `http://localhost:8000/*`
- Max 50 entries, 5-minute expiration
- Tries network first, falls back to cache
- Good for real-time data (exams, questions)

### Image Cache (Cache-First)
- Pattern: `*.jpg`, `*.png`, `*.gif`, `*.webp`, `*.svg`
- Max 100 entries, 1-hour expiration
- Uses cache first, falls back to network
- Good for static assets

## Development

### Building
```bash
npm run build
```
The PWA manifest and service worker are automatically generated by vite-plugin-pwa.

### Local Testing
```bash
npm run dev
```
Service worker won't register in dev mode (by design), but preview mode shows PWA features:
```bash
npm run build && npm run preview
```

Then visit `http://localhost:4173` to see PWA installation prompts.

### Testing Service Worker
1. Build the project: `npm run build`
2. Preview: `npm run preview`
3. Open DevTools → Application → Service Workers
4. You should see the registered service worker

### Cache Debugging
- DevTools → Application → Cache Storage
- View cached items by request URL
- Clear cache manually if needed for testing

## Security Considerations

- Service workers run on HTTPS only (localhost is exempt)
- All cached data is stored locally in IndexedDB/Cache API
- No sensitive auth tokens cached (handled separately)
- Cache validation ensures data freshness
